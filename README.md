# 记账本（微信小程序 / 网页 / Android 三端）

一个**零后端、纯本地存储**的个人记账工具，支持**导入微信支付账单 / 支付宝账单 / 银行流水**。

> 数据全部存在本机（`localStorage` / `wx.Storage`），**不联网、无账号、无云端**，导入的账单不会离开你的设备。
>
> 📦 **Android 安装包**：见 [Releases](https://github.com/lijunjie469/wechat_cost/releases) 下载最新 APK。

## 三端能力对比

| 能力 | 微信小程序 | 网页版 (`web/`) | Android APK |
|---|:---:|:---:|:---:|
| 记账 / 统计 / 预算 / 账户 / 日历 / 周期账单 | ✅ | ✅ | ✅ |
| 导入 CSV / XLSX / DOCX 账单 | ✅ | ✅ | ✅ |
| 导入 **PDF** 银行流水 | ❌（主包 2MB 放不下 pdf.js） | ✅ | ✅ |
| 数据存储位置 | `wx.Storage` | 浏览器 `localStorage` | WebView `localStorage` |
| 运行方式 | 微信内 / 开发者工具 | 任何浏览器打开 `web/index.html` | 安装 APK，离线可用 |

## 功能

- **账单首页**：按月浏览，支出 / 收入 / 结余汇总，按日分组列表，连续记账天数
- **记一笔**：支出 / 收入切换、16 个常用分类、自定义数字键盘、备注、日期、**账户选择**
- **编辑 / 删除**：点击账单进入编辑，长按账单或编辑页按钮删除
- **预算管理**：每月总预算 + 分类预算，首页进度条 + 超支变红，记账超出预算时弹窗提醒，可一键参考上月
- **账户与转账**：现金 / 微信 / 支付宝 / 银行卡等多账户，自动算余额与总资产，支持账户间转账（不计入收支）
- **周期账单**：房租、订阅、工资等固定收支设模板，打开小程序时自动补记到期账单（extId 幂等，不会重复）
- **记账日历**：按月日历展示每天收支，点日期看当日流水，漏记一目了然
- **统计**：总览环形图、**近 6 个月趋势 + 环比**、交易对手、金额区间与大额支出专项
- **流水明细**：日期区间 / 类型 / 分类 / 关键词筛选，分页加载
- **导入账单**：读微信支付 `.xlsx` / `.csv`、Word `.docx` 表格、银行流水 `.pdf`，自动归类、自动去重
- **合并多份账单**：导入页可勾选「合并多份账单」，把微信账单与银行流水累加到同一份预览再一次性导入
  - **导入口径按「本批有没有银行流水」自动切换**：
    - 含银行流水 → **以银行为准**：配对成功时保留银行流水的金额/日期/方向，商户名和分类从微信/支付宝账单补进来；退款不再冲减（退到卡的钱由流水那条入账体现）
    - 只有微信 / 只有支付宝（或两者一起但没流水）→ **各按自己的账单来**：不同账单之间不做配对，互不吞并；退款按账单自己的口径冲减原支出
  - 跨源判重：绑卡消费会同时出现在「微信/支付宝账单」和「银行流水」里（日期、金额、方向都相同，但一个显示商户昵称、一个显示收款人实名）。判定依据是「商户名一致」或「微信账单里支付方式明确是这张银行卡」，命中就只留一条、保留信息更全的那份
  - 实测（三份一起）：微信 285 + 支付宝 171 + 招行 519 = 975 笔 → 合并后 821 笔
  - 只认同一家银行：支付宝走「邮储信用卡」的记录不会被招行流水吞掉（实测 170 笔邮储记录一条不少）
  - 微信 285 笔 + 招行 519 笔单独合并时：去掉的 103 笔正好等于微信账单里「招商银行储蓄卡」的 103 笔、13,133.49 元，分毫不差
  - 同一份账单里同店同额同日的多笔仍然全部保留；走别的卡（如邮储信用卡）的记录不会被误合
- **按商家展示**：列表与统计都显示真实商户名（美团、Valve、上海拉扎斯…），交易对方只是「支付宝 / 微信支付 / 快捷支付」这类渠道名时自动退回备注，并标成「支付宝（渠道）」
- **备份与恢复**：JSON 备份导出/恢复（合并或覆盖）、CSV 导出（Excel 可开）、清空数据

## 导入微信支付账单

### 拿到账单文件

1. 微信 → 我 → 服务 → 钱包 → 账单
2. 右上角「常见问题」→ 下载账单 → 用于个人对账
3. 选时间范围 → 填邮箱 → 收到账单文件（解压密码在微信消息里发给你）
4. 把账单文件（`.xlsx` 或 `.csv`）发到「文件传输助手」

### 导入

首页 →「📥 导入微信支付账单」→「从聊天记录选择账单文件」→ 选刚发到聊天里的账单 → 核对预览 → 确认导入。

**支持的文件格式**

| 格式 | 支持 | 说明 |
|---|---|---|
| `.csv` / `.txt` | ✅ | 微信支付导出的原始格式 |
| `.xlsx` | ✅ | 解压后解析 sheet XML，无第三方库 |
| `.docx` | ✅ | 解析 `word/document.xml` 里的表格（自动挑最像账单的那张） |
| `.doc` | ❌ | 老版二进制 Word，请先另存为 `.docx` |
| `.pdf` | ✅（仅 APK/网页版） | 内置 pdf.js 解析文字层；银行流水（招行等）实测 22 页 519 笔 100% 对齐 |

**支持的三类账单**

| 来源 | 格式 | 关键列 |
|---|---|---|
| 微信支付 | `.xlsx` / `.csv`（UTF-8） | 支付方式 → 用于和银行流水判重 |
| 支付宝 | `.csv`（**GBK 编码**，小程序端已内置解码表） | 收/付款方式 → 同样用于判重 |
| 银行流水 | `.pdf` / `.xlsx` / `.csv` | 借记/贷记 或 金额正负号 |

支付宝账单的处理（和账单头部数字对齐）：
- **退款看本批有没有银行流水**：
  - 有流水 → 渠道账单按**原始支出**记账，退款不重复冲减（退到银行卡的钱已经在流水里有入账；
    实测支付宝退款 2,328 元在招行只入账 2,027 元，差的 301 退到了花呗，两边都算会重复）
  - 没有流水 → 按账单自己的口径，退款冲减原支出（实测支付宝 10 笔退款里，有 2 笔对应原单
    交易成功、已冲减 2,427 元；其余 8 笔的原单本来就是「交易关闭」，本就没记账）
  - 找原单的顺序：**交易订单号**（退款行与原订单前半段相同）→ 商品说明里的「订单号：…」→ 同商户且金额完全相同。
    绝不按「金额最接近」乱配，否则 99 元退款会被冲到别的 189 元订单上
- **未成交剔除**：`交易关闭 / 交易失败 / 还款失败` 一律不计（实测剔除 8 笔）
- **平台名回退**：「交易对方」是「淘宝闪购」这类平台名时，商家取「商品说明」里的具体店铺

**PDF 说明**

- **APK / 网页版**：直接选 `.pdf` 就能解析（内置 pdf.js，纯本地，不联网）
- **小程序端**：主包 2MB 放不下 pdf.js，请先用 WPS「另存为 Excel/CSV」，或长按表格复制后
  粘贴到导入页文本框（粘贴解析支持 **Tab / 逗号 / 连续空格** 三种分隔）
- **扫描件 / 图片型 PDF** 没有文字层，读不出来，需要 OCR，暂不支持
- **加密 PDF**（要密码打开）不支持

已适配的银行流水形态：招行（双语表头 + 货币列 + 金额正负号）、借贷分列的中行/工行样式、
微信支付账单 PDF。实测招行 22 页 519 笔与原始表格逐笔对齐、收支合计完全一致。

电脑上做开发时也可以直接把 CSV / 表格文本粘进导入页的文本框（模拟器里最方便）。

### 解析规则

| 处理 | 规则 |
|---|---|
| 表头定位 | 自动找到包含「交易时间」「金额(元)」的那一行（账单前面有 17 行说明文字也没关系） |
| 分隔符 | 自适应 **Tab / 逗号 / 连续空格**（Excel、PDF、网页复制出来的文本都能直接粘） |
| 日期 | 支持 `2026-10-22 12:30:45` 与 Excel 日期序列号（`46317.49`） |
| 金额 | 支持 `¥1,234.50` 和纯数字 `77.6` |
| 跳过 | 「不计收支」（提现 / 信用卡还款 / 零钱通存取等）、**已全额退款**、金额异常行 |
| 归类 | 按「交易类型 + 交易对方 + 商品」关键词映射到 10 个支出分类 / 6 个收入分类 |
| 去重 | 用微信「交易单号」作唯一键，重复导入同一份账单不会重复入账 |

> 已全额退款的收支是成对出现的，跳过两笔对「结余」没有影响；因此本应用的统计合计会和微信账单页顶部的总额相差这部分金额。

## 如何运行

**方式一（推荐给调试用）**：微信开发者工具 → 导入项目 → 选择本目录

- 新版工具（2.02+）已不支持游客 AppID（`touristappid`），创建项目会报「系统错误，错误码 1」
- 当前可用做法：用 **1.06.x 旧版**开发者工具，登录页点「游客模式」，再用 `touristappid` 创建/导入项目

**方式二**：注册小程序拿到真实 AppID，填进 `project.config.json` 的 `appid`，即可真机预览

**方式三：Android APK**

- 从 [Releases](https://github.com/lijunjie469/wechat_cost/releases) 下载最新 `jizhangben-vX.Y.Z.apk` 直接安装（当前 **v1.1.5**）

- 本质是 WebView 外壳，内嵌 `android/app/src/main/assets/www`（由 `web/` 同步而来），通过 `https://app.local/` 拦截 assets 提供页面，规避 `file://` 的 localStorage 限制
- 比小程序多一个能力：**能直接解析 PDF 账单**（内置 pdf.js legacy 版，约 1.5MB，小程序主包 2MB 放不下）
- 重新打包：
  ```bash
  # 1. 同步前端资源
  rm -rf android/app/src/main/assets/www && mkdir -p android/app/src/main/assets/www && cp -r web/* android/app/src/main/assets/www/
  # 2. 改 android/app/build.gradle 里的 versionCode / versionName
  # 3. 构建（本机无系统 gradle，用 wrapper 缓存里的）
  cd android && ANDROID_HOME=D:/Android/sdk \
    "/c/Users/15398/.gradle/wrapper/dists/gradle-8.11.1-bin/*/gradle-8.11.1/bin/gradle.bat" \
    assembleRelease --no-daemon
  # 产物：android/app/build/outputs/apk/release/app-release.apk
  ```
- 签名用的 `android/app/keystore.jks`（口令见 build.gradle），版本号递增后可直接覆盖安装

## 数据说明

- 账单保存在本地 `wx.Storage`，key 为 `wc_records_v1`；设置（账户/预算/周期模板）存 `wc_settings_v1`
- 记录结构：`{ id, type: 'expense'|'income'|'transfer', amount, categoryId, note, date, accountId, createdAt }`
- 转账记录额外带 `toAccountId`；导入的记录带 `extId`（微信交易单号，用于去重）、`source: 'wechat'`、`party`、`tradeType`
- 周期账单生成的记录带 `extId = 'rc:<模板id>:<日期>'`、`source: 'recurring'`
- 清除小程序缓存会清空数据 → 请用「设置 → 导出 JSON 备份」定期备份；导入微信账单时会自动去重
